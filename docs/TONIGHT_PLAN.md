## 原计划的实现范围

沿用已选择的原版 Terraria 1.4.5.8，使用自写、固定用途的 Host 与 C# Bridge，仅引入固定官方 NuGet `Lib.Harmony 2.3.3`。不加载上游 Core、Injector、Vault、DebugTools 或可选游戏模组，不运行上游批量部署脚本。实际原版接口已静态核实，补丁加载和游戏行为尚待实测。

桥接第一版只输出自身位置、速度、生命、死亡状态和控制会话，不输出地形或矿物。本地连续控制器执行右移、停止和跳跃；规则状态机安排动作顺序，游戏运行时不调用模型或付费 API。

输入默认交给人类，显式启用后才允许 Agent 操作。动作带会话、世界标识、递增序号和有效期，初始最大有效期为 250 毫秒，用单调真实时间计时。断连、过期、死亡、退世界、进入菜单或文本输入、异常和紧急停止均清空动作；人工接管后保持停控，重连不能自行恢复。通信采用明确拒绝远程客户端的管道，或严格绑定本机回环地址并校验会话；后台通信线程不读游戏对象。具体接口、热键和停控延迟以本机核实与实测为准。

## 进入游戏前的门槛

已有 21 个存档相关文件备份和 16017 个游戏副本文件校验记录。后续重新备份时仍须在游戏关闭且存档同步完成后只读复制，保留校验清单。桌面交接后，核实自有 Host/Bridge 的实际加载、资源根与独立存档路径，在人物与世界加载前检查实际 SavePath；路径不符立即退出。不得凭命令行参数或编译就认定隔离成功，也不得为排错打开现有角色或世界。

同时核实实验流程不会显示、加载或写入原有云存档。实际存档路径或 Steam Cloud 影响任一尚未确认，都不得创建或加载人物、世界。

隔离确认后，新建 Classic 人物和 Classic 小世界，正常生成、腐化环境、不使用特殊种子，配置沿用一天计划并记录实际版本与创建界面。首次创建可以由人类操作，记为人工准备；验收中的移动和跳跃由控制器执行。

若前 50 分钟仍无法核对加载来源或确认存档隔离，后续时间继续解决这个阻塞并保留离线测试结果。不能安全进入游戏时，不冒险启动、不宣称 A 通过。

## 实机验收清单

1. **观察**：日志持续更新角色位置，与画面中的角色对应；没有隐藏世界数据。
2. **右移、停止、跳跃**：在可通行地面短距离右移；停止后输入标志释放；跳跃时出现可核实的纵向位置变化。停止允许正常惯性，不要求速度瞬间归零。
3. **失联与过期**：运动中终止控制器，并单独停止续期；输入在有效期加一个可执行游戏更新内释放，日志记录实际延迟。重启控制器后保持停控，直到显式启用。
4. **控制权与生命周期**：实测紧急停止、人工接管、暂停恢复、菜单和文本输入、退世界；核对异常与死亡处理，并在真实死亡后检查输入清空与复活后停控。旧会话、错误世界标识、重复或乱序动作不能重新生效。
5. **重复运行**：目标是连续完成 3 次基础动作流程；安全项逐项记结果。未测试的项目写“未验证”，全部必需项完成后才记录 A 通过。

死亡通过正常游戏发生，不改血量、不刷怪来伪造验证条件。每次测试记录动作、实际结果、失败原因、死亡和人工接管次数。暂停期间旧动作按真实时间失效，恢复时不得执行；停止延迟的验收同时看输入标志和画面。

卡住或结果不符合预期时，立即停止并重新观察，最多重试 2 次。达到重试上限就记录失败并修复；不无限重复相同动作。
